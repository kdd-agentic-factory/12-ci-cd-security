# Pull Request Policy

## Objetivo

Hacer que cada cambio sea revisable, trazable y verificable.

## Requisitos

- Describir el proposito del cambio y su impacto.
- Vincular issues, tareas o decisiones tecnicas relacionadas.
- Incluir evidencia de pruebas o explicar por que no aplica.
- Mantener el alcance del pull request lo mas pequeno posible.
- No mezclar refactors amplios con cambios funcionales salvo que sea necesario.
- Actualizar documentacion cuando cambie el comportamiento.

## Criterios de revision

- Correctitud funcional.
- Riesgos de seguridad.
- Cobertura de pruebas.
- Compatibilidad hacia atras.
- Observabilidad y operacion.
- Claridad de codigo y mantenimiento.
